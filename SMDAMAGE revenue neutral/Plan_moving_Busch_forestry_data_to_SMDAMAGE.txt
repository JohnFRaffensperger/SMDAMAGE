Architecture decision
- Runtime database remains Data/smdamage_data.db.
- create_database.py is the integration boundary: it imports/transforms forestry data from Output/Databases/Busch2024_to_SMDAMAGE.sqlite into Data/smdamage_data.db.
- database_interface.py continues to read only from Data/smdamage_data.db at runtime.
- Implementation path is direct import from Busch SQLite into Data/smdamage_data.db; no intermediate forestry files are required for runtime.
- Direct-import forestry load should run in one database transaction and roll back on any validation failure.
- Remove/create_database.py forestry assumptions:
	- create_database.py still hardcodes forestry as a multi-column CSV layout with fixed column indices.
	- Data/Forestry_bid_steps.csv is still a wide file with one shared quantity column and fixed forestry price columns.
	- Replace the legacy 9-column forestry inputs with bidder-specific forestry data keyed by (rotation_year, cluster_index).

1. Forestry bidder metadata
Columns: bidder_name, rotation_year, cluster_index, contract_years, available_area_mhectares, hector_name, description
- Unique key: bidder_name
	- Required non-null: bidder_name, rotation_year, cluster_index, contract_years, available_area_mhectares
	- Domain checks: rotation_year > 0, contract_years = rotation_year, available_area_mhectares >= 0

2. Forestry bid steps data
Columns: bidder_name, bid_step, price_per_hectare, quantity_mhectares
- Unique key: (bidder_name, bid_step)
- Required non-null: bidder_name, bid_step, price_per_hectare, quantity_mhectares
- Domain checks: bid_step >= 1, quantity_mhectares >= 0

3. Forestry carbon removal data
Columns: bidder_name, year, tons_per_hectare_per_year
- Unique key: (bidder_name, year)
- Required non-null: bidder_name, year, tons_per_hectare_per_year
- Domain checks: year integer in modeled horizon, tons_per_hectare_per_year numeric

- available_area_mhectares = area_ha / 1_000_000

Source mapping from Busch SQLite

- Preferred area source: sum(area_ha) from Undiscounted_dta_output grouped by the pair.
- Metadata: contract_years = rotation_year, available_area_mhectares = sum(area_ha) / 1_000_000.

B. Carbon removal schedules
- Source from carbon_removal_schedules by (rotation_year, cluster_index, year).
- Emit one row per bidder-year as tons_per_hectare_per_year (tC_per_ha_per_year from source).
* Area quantities can diverge between Undiscounted_dta_output and forestry_bid_curves; apply thresholded validation: log warning when abs(delta_area_ha) <= 1e-6 * max(1, reference_area_ha), and fail import when above threshold.
* Normalize selected_rotation_year_int and selected_rotation_year with one rule: rotation_year = int(round(value)); assert equality after normalization for all joined forestry records.

C. Bid steps
- First pass: source from forestry_bid_curves filtered to one discount_rate (default 0.03).
- Required source fields in forestry_bid_curves mapping (exact names):
	- selected_rotation_year_int -> rotation_year
	- cluster_index
	- discount_rate
	- bucket_id -> bid_step ordering
	- area_ha_sum -> quantity_mhectares via / 1_000_000
	- npv_column -> price_per_hectare source-column selector
- Required source fields in Undiscounted_dta_output used for npv_column validation:
	- NPV_0_pct_per_ha
	- NPV_015_pct_per_ha
	- NPV_03_pct_per_ha
	- NPV_06_pct_per_ha
- Discount-rate mapping requirement:
	- 0.0 -> NPV_0_pct_per_ha
	- 0.015 -> NPV_015_pct_per_ha
	- 0.03 -> NPV_03_pct_per_ha
	- 0.06 -> NPV_06_pct_per_ha
	- Exporter must assert that forestry_bid_curves.npv_column matches the expected mapped value for selected discount_rate.
- Bid-step ordering:
	* Authoritative step order is bucket_id ascending within (selected_rotation_year_int, cluster_index, discount_rate).
	* When deterministic tie-breakers are required, sort by npv_max_per_ha, then area_ha_sum.
	* Price is validated as nondecreasing across ordered steps; if violated, fail import.
	- quantity_mhectares is incremental per step: area_ha_sum / 1_000_000.
