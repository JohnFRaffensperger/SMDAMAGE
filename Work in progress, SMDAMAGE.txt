Plan: update SMDAMAGE revenue neutral.py to use new forestry data in smdamage_data.db

Goal
- Make SMDAMAGE revenue neutral.py consume forestry bids and land-cap metadata from the new schema:
  - bids.discount_rate (all forestry rates stored)
  - forestry_bidder_metadata.available_area_mhectares (explicit bidder max area)
- Preserve behavior for non-forestry bidders and existing objective/constraint logic.

Current state to account for
- smdamage_data.py contains forestry bids for all discount rates and forestry_bidder_metadata.
- read_bids(scenario) currently reads all bids by bidder and period without regard to discount rate.
- read_bids(scenario) must be updated to retrieve forestry bids for the selected scenario discount rate.
- Land constraints currently use bidders with units == mhectares and bidder.contract_years, but no explicit metadata table lookup.

Design decisions
1) Bid retrieval by discount rate
- Forestry bidders: pull only rows where bids.discount_rate matches scenario.discount_rate_base.
- Non-forestry bidders: keep discount_rate NULL and include them regardless of scenario rate.
- Keep scenario.discount_rate(t - StartYear) multiplier in objective coefficient construction unless intentionally changing economics.

2) Forestry max area source of truth
- Use forestry_bidder_metadata.available_area_mhectares as the authoritative max area for each forestry bidder.
- Use bidders.contract_years for contract window logic (already set from rotation year).

3) Land constraints
- Replace pooled forestry land cap with bidder-specific constraints:
  for each forestry bidder f and model period t,
  	sum_{u active at t} vpt[f, u] <= available_area_mhectares[f] with active condition: u <= t and t <= u + contract_years[f] - 1.

Implementation steps

A. database_interface.py updates
- Add function get_forestry_metadata():
  - SELECT bidder, rotation_year, cluster_index, available_area_mhectares FROM forestry_bidder_metadata
  - return dict keyed by bidder for fast lookup.
- Keep get_bids(bidder_name, discount_rate=None) behavior:
  - if discount_rate provided, include bidder rows with discount_rate IS NULL OR rate match.
  - this preserves non-forestry bids while filtering forestry by scenario rate.

B. SMDAMAGE revenue neutral.py read_bids(scenario)
- Continue iterating over Bidders = database_interface.get_bidders().
- For each bidder_name, call get_bids(bidder_name, scenario.discount_rate_base).
- Add a check for forestry bidders (units == 'mhectares' and discount_rate not NULL):
  - if no bids returned for the scenario rate, fail fast with a clear message listing bidder and requested rate.
- Keep existing unit conversion behavior for kt bidders.

C. SMDAMAGE revenue neutral.py land constraints
- Load forestry metadata once before building land constraints:
  forestry_meta = database_interface.get_forestry_metadata()
- Define Foresters as bidders where units == 'mhectares' and discount_rate not NULL.
- Build one land constraint per forestry bidder per period using forestry_meta[bidder]['available_area_mhectares'].
- Use bidder.contract_years from get_bidders() for active contract windows.
- Fail fast if a forestry bidder in bidders has no metadata row.

D. Optional consistency checks (recommended)
- At model setup:
  - check set(Foresters) == set(forestry_meta keys); if not, raise with missing/extras.
  - check scenario.discount_rate_base exists among forestry bids (for at least one forestry bidder).

Validation plan
1) Database-level checks after create_database.py
- Query distinct forestry discount rates in bids and confirm expected set (e.g., 0.0, 0.015, 0.03, 0.06).
- Query forestry_bidder_metadata row count equals number of forestry bidders in bidders.

2) Model input checks
- Run read_bids(scenario) for each supported scenario discount rate and verify:
  - forestry bidders receive non-empty bid lists
  - non-forestry bidders unaffected

3) Constraint checks
- On solved model output, verify each forestry bidder-period utilization does not exceed available_area_mhectares.
- Confirm no KeyError/missing metadata failures.

4) Regression checks
- Solve at least one baseline scenario and compare:
  - solution status remains optimal/feasible
  - objective remains in expected range
  - output file generation unchanged.

Potential pitfalls
- Double-discounting concern: if forestry bids already encode NPV at selected discount_rate, applying scenario discount_rate(t - StartYear) over time may be intended or may over-discount depending on model economics; keep current behavior unless changing model design deliberately.
- Floating comparison on discount rates: use tolerance in SQL (already done via ABS(discount_rate - ?) < 1e-12).
- Missing forestry rate rows for uncommon scenario rates should fail fast with actionable error text.

Deliverables
- Updated database_interface.py query helpers.
- Updated SMDAMAGE revenue neutral.py read_bids and land-constraint sections.
- Short verification log showing:
  - selected discount rate,
  - forestry bidders loaded,
  - metadata row count,
  - successful solve status.
